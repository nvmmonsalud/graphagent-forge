# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

GraphAgent Forge is a hackathon project (Daytona HackSprint Tokyo 2026): a FastAPI-based agent that ingests URLs/text, extracts entities with Kimi AI (Moonshot), stores them as a knowledge graph in Neo4j, and answers questions via GraphRAG.

## Commands

```bash
cp .env.example .env                 # configure API keys (app boots with none, degraded)

python -m src.main                   # run FastAPI server on :8000 (uvicorn; reload opt-in, see DEV_RELOAD)
streamlit run frontend/app.py        # optional Streamlit dashboard (API base via GRAPHAGENT_API)
python -m scripts.seed_graph         # loads seed/graph.json (a few sample documents) for demos
python -m scripts.seed_graph --dry-run|--reset|--clear   # validate only / drop seed sources + reseed / drop only

ruff check src/ scripts/ tests/      # lint (config in pyproject.toml: E,F,I,UP,B, line 100)
pytest                               # offline suite — no keys/Neo4j needed (integration deselected)
pytest -m integration                # extra tests against a live Neo4j (reads NEO4J_* env, else skips)
```

Some tests guard docs and static files, not code: `tests/test_docs_claims.py` fails if README.md/DEMO_PITCH.md contain banned marketing claims (e.g. "sub-second", "485 nodes"), requires this file to mention `ingest/file`/`file_extractor`, and requires DEMO_PITCH's scripted question to match the frontend placeholder. `tests/test_frontend_*.py` assert on text in `frontend/index.html`. Run `pytest` after editing docs or the frontend.

## Architecture

M1 source publication and semantic-index upgrade procedures are in `docs/M1_UPGRADE.md`; review them before changing ingestion, deletion, merge or embedding code. Source writes share a graph mutation lock. Embedding writes compare the captured label/summary so stale provider results cannot restore deleted evidence.

Two pipelines share state initialized in `src/main.py`'s lifespan hook (`app.state.neo4j`, `app.state.agent`, `app.state.ws_manager`, `app.state.neo4j_available`). Startup tolerates an unreachable Neo4j: the server boots degraded, `/api/health` reports `{"status": "degraded", "neo4j": false}`, and graph routes return 503.

**Ingestion** (`GraphAgent.ingest_url` / `ingest_text` / `ingest_file` in `src/agent/core.py`):
`src/ingestion/extractor.py` (fetch + clean HTML; SSRF guard: http/https only, all DNS records checked, manual redirect re-validation, 3MB streamed cap, content-type gate; the shared client's `_GuardedNetworkBackend` re-resolves at connect time and connects to the validated IP, which defeats DNS rebinding, and `trust_env=False` keeps proxy env vars from bypassing it; client-facing fetch errors are the fixed `ERR_*` literals — resolved IPs, internal hostnames and raw socket errors are only logged, since job results are broadcast) — or, for uploads, `src/ingestion/file_extractor.py` (PDF/TXT/MD from raw bytes; see the file-upload subsection below) — → `src/ingestion/graph_writer.py` (orchestrates; prefixes new node IDs with a SHA-256 source/version namespace; legacy seed IDs retain the md5 prefix; drops edges referencing unknown IDs, reports `dropped_edges`) → `src/ingestion/entity_parser.py` (Kimi LLM extracts nodes/edges as JSON; structured error when `KIMI_API_KEY` is missing; the JSON is untrusted, so `graph_writer.sanitize_graph` drops malformed items, clips every string field and caps a single extraction at `MAX_NODES`/`MAX_EDGES` before `prefix_and_validate`; the agent captures at most 200,000 normalized characters and extracts at most twelve overlapping 8,000-character chunks (first 91,600 unique characters), reporting skipped coverage; helper defaults remain 50,000 characters) → `src/graph/neo4j_client.py` (writes `:Entity` nodes and `:RELATES_TO` edges in one transaction). After a successful write, `_post_ingest` (shared tail): stores per-entity embeddings (`label: summary` per node via `set_node_embeddings`), optionally auto-merges exact-label duplicates (`AUTO_MERGE=exact`), broadcasts that source's nodes/edges over WebSocket `/ws/graph`, and runs integrity verification (scoped to the ingested source) in a Daytona sandbox. Progress stages reported to the job queue, in order: `fetching` (URL only) / `parsing` (file only) → `extracting` → `embedding` → `merging` (only when `AUTO_MERGE=exact`) → `broadcasting` → `verifying`.

**Query** (`GraphRAGEngine.query` in `src/graph/graphrag.py`):
Semantic vector candidates (compatible Nosana metadata only) plus keyword matches provide bounded entity context. Original excerpts are also searched independently, including when no entity matches. `answer_with_citations` receives at most three excerpts/24,000 characters as untrusted data. JSON citation/conflict IDs must reference the exact sent set, and the entire sent set is revalidated against current source versions after generation. Graph summaries remain diagnostics, not original evidence. Statuses are `no_context`, `llm_unavailable`, `insufficient_evidence`, or `answered`; clients classify by status. `answer_query` remains a compatibility helper. Evidence GET endpoints enforce optional configured API-key auth. See docs/M2_CONTRACT.md and docs/M2_UPGRADE.md.

HTTP endpoints live in `src/api/routes.py` (mounted at `/api`); they pull `agent`/`neo4j` off `request.app.state`. Security middleware/deps: optional `X-API-Key` auth (only when env `API_KEY` is set) on mutating routes, `/ask`, and the credit/CPU-spending sandbox routes (`SANDBOX_DEP`: `/graph/verify`, `/graph/verify/fanout`, `/graph/verify/sweep`, `/graph/analytics`). The web UI's `apiFetch` sends a key stored in localStorage and asks for it via the in-page dialog on a 401. Native `prompt`/`alert`/`confirm` are banned by the frontend tests. In-memory per-IP rate limiting (`RATE_LIMIT_MAX`, default 10/min, read once at import time — not per-request — shared across `/ingest/*` and `/ask`, per-process); the sandbox routes use a separate `SANDBOX_RATE_LIMIT_MAX` bucket (default 6/min, `sandbox:`-prefixed keys in the same `_rate_buckets` dict), and only one fan-out/sweep batch may run per process (`_sandbox_batch_lock`, second caller gets 429). Local-fallback subprocesses are capped process-wide by `DaytonaExecutor._local_gate()`. `SecurityHeadersMiddleware` adds `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy` and a CSP (`'unsafe-inline'` is needed for the single-file UI; no third-party scripts, D3 is vendored, fonts only from Google Fonts). A new external resource in the frontend must be added to `CONTENT_SECURITY_POLICY` or the browser will block it. `/docs`, `/redoc` and `/openapi.json` are off unless `ENABLE_API_DOCS=1`. Rate-limit keys are the client IP, with IPv6 grouped by /64 (`_client_key`). `BodySizeLimitMiddleware` in `src/main.py` (outermost) rejects any request body over `MAX_REQUEST_BYTES` (4MB) with 413, by Content-Length or while streaming, before FastAPI parses it or auth runs. `/ws/graph` refuses browser Origins not in `ALLOWED_ORIGINS` (same-origin is always allowed; no Origin, i.e. non-browser clients, is allowed) with close code 1008, caps sockets at `MAX_WS_CONNECTIONS` (1013), and `broadcast` sends concurrently with a 2s per-socket timeout, dropping stalled clients. Bind defaults to loopback (`APP_HOST=127.0.0.1`; docker compose publishes the app and Neo4j on 127.0.0.1 only), CORS origins from `ALLOWED_ORIGINS`, 500s log server-side (`log.exception`) and return only `"internal error"` to clients. `GET /graph/data` without `source_doc` accepts `?limit=` (1–5000, default 500) capping the all-sources node set; `get_all_graph_data` returns `{"nodes", "edges", "truncated", "total_nodes", "total_edges", "limit"}` — `truncated` is true whenever the real counts exceed what was returned. The **boundary-node invariant still holds under the cap**: the edge query is constrained to the node ids actually returned (`WHERE a.id IN $ids AND b.id IN $ids`), so a capped read never emits an edge to a node the client wasn't given — edges are truncated independently and more generously, since an orphaned node (no edge) renders fine in D3 but a dangling edge endpoint does not. `get_graph_data_by_source` returns the same shape with `truncated: false` (per-source reads are never capped). New per-source or all-graph read queries must preserve both the shape and the invariant.

### Ingest job queue

Ingests run through a submit-then-track queue (`src/agent/jobs.py`, `JobManager` on `app.state.jobs`, created and `start()`ed in the lifespan hook right after `ws_manager`). A route calls `jobs.submit(kind, params, run)` and returns the queued job record immediately; 2 workers pull from an `asyncio.Queue` and execute the injected async `run(progress_cb)`, which reports stages back. Every transition (queued → running → each stage → terminal) is broadcast over `/ws/graph` as `{"type": "job_update", "job": {...}}`; clients can also poll `GET /api/jobs/{id}` or pass `?wait=true` on submit as a synchronous escape hatch. `INGEST_JOB_TIMEOUT` (default 600s) caps a single job.

Status semantics matter: **`failed` means the job crashed — unhandled exception, timeout, or shutdown, nothing else.** A business failure (bad URL, missing `KIMI_API_KEY`, 0 entities) is a *`succeeded`* job whose `result.success` is false. `error` is only ever one of three literals — `"internal error"`, `"timed out"`, `"server shutdown"`; raw exception text is logged via `log.exception` and must never reach the record. `jobs.py` stays generic: it imports neither `src.main` nor `src.agent.core` (the broadcast sink is injected), and treats `params`/`result` as opaque dicts.

The registry is in-memory and per-process — jobs vanish on restart. Uvicorn's `reload=True` restarts the process on every file save, which kills any in-flight job the same way, so `reload` is **opt-in**: `python -m src.main` only passes `reload=True` when `DEV_RELOAD=1` is set (default off — leave it unset for demos/rehearsals, set it while iterating on code). `shutdown()` runs first in the lifespan `finally` (before the Neo4j driver and shared httpx clients close) so in-flight jobs can drain; whatever is still queued/running is failed with `"server shutdown"` and its waiters unblocked. Finished jobs beyond `history_limit` (100) are evicted oldest-first; `submit` raises `JobQueueFull` once queued+running hits `max_active` (20).

### Graceful-degradation pattern

Every external sponsor service has a local fallback, so the app runs with zero configured keys:

- **Daytona** (`src/agent/daytona_exec.py`): sandboxed code execution → falls back to local subprocess (30s timeout) if SDK/key missing. The verify path pipes the graph JSON via stdin locally (argv is capped at ARG_MAX; do not embed large payloads in `-c` scripts). `verify_graph` returns exactly one of two shapes: **ran** — `{"ok": true, "valid": bool, ..., "method": "daytona"|"local", "duration_ms": int}` (plus `boot_ms` and `sandbox_id` on the Daytona path); **failed** — `{"ok": false, "error": <literal>, "method": ..., "duration_ms": int}` with no `valid` key at all, so a failed-to-run result can never be mistaken for a real integrity verdict. `error` is one of two client-facing literals (`VERIFY_ERROR_UNAVAILABLE` = `"verification unavailable"`, `VERIFY_ERROR_TIMEOUT` = `"verification timed out"`); the real exception goes to `log.exception`/`log.error`, never to the client. `duration_ms` and `boot_ms` are measured with `time.perf_counter()` at call time — never hardcode or assume a boot time.
- **Daytona fan-out** (`verify_graph_fanout(graphs, *, on_event=None, max_concurrency=None)`, same module): one ephemeral sandbox per `source_doc -> graph payload` entry, all launched together behind a semaphore, so wall clock is bounded by the slowest single audit instead of the sum. Same two-shape contract as `verify_graph`: **ran** — `{"ok": true, "sources": [...], "source_count", "sandbox_count", "wall_ms", "serial_ms", "speedup", "concurrency", "boot_ms": {count,min,max,avg}|null, "method"}` where each `sources` item carries its own `verify_graph` verdict (`valid`/... or `error`), so one source failing never sinks the batch; **failed** — `{"ok": false, "error": FANOUT_ERROR_UNAVAILABLE ("fan-out verification unavailable"), "method", "wall_ms"}` with **no `sources` key** (only when every source failed; empty `graphs` is a valid zero-source run). Default concurrency comes from `FANOUT_MAX_CONCURRENCY`, read once at `DaytonaExecutor` construction (default 6, invalid values log and fall back), clamped 1..32; passing `max_concurrency=n` bypasses that default but still hits the hard clamp of 32. `wall_ms`/`serial_ms`/`speedup` are measured, never asserted.
- **Daytona sweep** (`verify_graph_sweep(graph_data, *, sizes, on_event=None)`): replicates ONE payload N times (`{"audit-01": g, ..., "audit-NN": g}`) and calls `verify_graph_fanout(..., max_concurrency=n)` for each `n` in `sizes`, so it measures parallel throughput of the same audit, never N distinct documents — the envelope says so with `replicated: true`, and the route adds `source_doc`, `distinct_sources: 1`, `payload_nodes`, `payload_edges`. Sizes run **sequentially on purpose** (sandboxes share the account's CPU budget; overlapping sizes would corrupt the curve), so `total_wall_ms` is the sum of per-size `wall_ms`. Each `results` item is `{"n", "ok", "sandbox_count", "short_by", "wall_ms", "serial_ms", "speedup", "boot_ms", "method"}` (+ `error` when that size did not run); `short_by = n - sandbox_count` > 0 means the account refused sandboxes at its concurrent-CPU ceiling (Daytona 400 "Total CPU limit exceeded") — surface it, never average it away. Two shapes again: **ran** — `{"ok": true, "replicated": true, "results": [...], "sizes", "total_wall_ms", "method"}`; **failed** — `{"ok": false, "error": SWEEP_ERROR_UNAVAILABLE ("sweep unavailable"), "method", "wall_ms"}` with **no `results` key** (no size produced a verdict, or the route found no sources at all). The two error literals are deliberately distinct from each other and from the `VERIFY_ERROR_*` ones. For both features the `on_event` progress sink is **injected, never imported** — the same rule as the job queue — and a sink that raises is logged and ignored; `daytona_exec.py` must stay free of transport/`src.main` imports.
- **Nosana** (`src/agent/nosana_client.py`): GPU embeddings via `NOSANA_EMBEDDING_URL` → falls back to a deterministic uint32-derived hash pseudo-embedding (384-dim, unit-norm, always finite; non-finite remote vectors are rejected and fall back too). `get_embedding_result` returns per-call vector/method/model/version/dimension; `last_embedding_method` is diagnostic only; GraphRAG skips vector search when it's the hash fallback (hash embeddings aren't semantic). One `NosanaClient` instance is shared between `GraphAgent` and `GraphRAGEngine` — keep it that way.
- **Kimi** has no fallback — a missing `KIMI_API_KEY` returns structured errors (`{"error": "KIMI_API_KEY not configured"}`), never an SDK exception. The model comes from `KIMI_MODEL` env (resolved in `entity_parser._resolve_model`; don't hardcode it elsewhere). Moonshot's current Kimi models are reasoning models with two live-API constraints (verified 2026-09): `temperature` must be 1 (anything else is a 400), so **never pass `temperature`**; and thinking cannot be disabled, with reasoning tokens counting against `max_tokens` — budgets live in `EXTRACT_MAX_TOKENS` (16384, env `KIMI_EXTRACT_MAX_TOKENS`) and `ANSWER_MAX_TOKENS` (4096, env `KIMI_ANSWER_MAX_TOKENS`), and a `finish_reason == "length"` extraction returns the structured `TRUNCATED_ERROR` rather than a JSON parse error. Expect ~1 minute per ingest of a few thousand characters.
- **File upload** (`src/ingestion/file_extractor.py`, `POST /api/ingest/file`): PDF/TXT/MD uploads, capped at `MAX_UPLOAD_BYTES` (3MB) and read in bounded chunks so the handler never materializes more than that regardless of what Starlette already buffered. Two independent optional-import degradations, both import-time probes that must never raise: `pypdf` missing → `HAS_PYPDF = False`, PDF uploads return `ERR_NO_PYPDF` while TXT/MD keep working; `python-multipart` missing → `HAS_MULTIPART = False` in `src/api/routes.py`, and the whole `POST /ingest/file` route is conditionally **not registered at all** (`if HAS_MULTIPART: @router.post(...)`) rather than registered and failing per-request. PDFs are parsed in a killable child process (`_run_pdf_isolated`: `sys.executable -c`, bytes over stdin, JSON on stdout; RLIMIT_CPU and, on Linux, RLIMIT_AS set inside the child; `PDF_PARSE_TIMEOUT` wall clock; at most `PDF_PARSE_CONCURRENCY` at once; over `MAX_PDF_PAGES` = 300 is rejected), because a worker thread can't be cancelled when a job times out. Monkeypatching parse internals in tests won't reach the child; patch parent-side values (`HAS_PYPDF`, `PDF_PARSE_TIMEOUT`) or use real PDF bytes. Before trusting file content, `check_upload_shape`/`safe_filename` enforce: filename has no path separators/control chars and is under `MAX_FILENAME_LEN`; extension is one of `SUPPORTED_EXTENSIONS` (`.pdf`/`.txt`/`.md`); and **magic bytes win over the declared/extension type** — a leading `%PDF-`/`PK\x03\x04`/`MZ`/`\x7fELF` signature (or other binary sniff) on a file claiming to be `.txt`/`.md` is rejected as a mismatch even though the extension looked fine. A declared `Content-Type` that conflicts with the extension is also rejected, except for the meaningless values browsers send constantly (`""`, `application/octet-stream`, `binary/octet-stream`, and `None`), which are never treated as a conflict.

When touching these clients, preserve the fallback behavior and the `method` / `last_embedding_method` reporting fields.

### Graph schema

Single node label `:Entity` with properties `id` (unique constraint), `label`, `type`, `summary`, `norm_label` (indexed; from `src/graph/normalize.py:normalize_label` — compute it for any new node write), `source_docs` (LIST of provenance strings — membership tests use `$source_doc IN coalesce(n.source_docs, [])`; edges keep a scalar `r.source_doc` because an edge is a per-document assertion), `aliases` (list, set by merges), `embedding` + per-result method/model/version/dimension metadata; only active compatible Nosana vectors populate `semantic_embedding` on `:SemanticEntity` for the new 384-dim cosine index. All relationships are stored with the fixed label `:RELATES_TO`; the LLM's semantic relationship name lives in the `r.type` property, and every read path returns `coalesce(r.type, type(r))` — new queries must do the same or the UI/LLM will see the literal string `RELATES_TO`. Schema/indexes are created idempotently on startup by `Neo4jClient.init_schema`, which also runs the idempotent scalar-`source_doc` → `source_docs` migration and `norm_label` backfill (rollback recipe: `MATCH (n:Entity) WHERE n.source_docs IS NOT NULL SET n.source_doc = head(n.source_docs) REMOVE n.source_docs`).

### Entity dedup/merge

Suggest-only by design: `GET /api/graph/duplicates` returns tier-1 (exact `norm_label` match across differing source sets) and tier-2 (embedding cosine ≥0.9, only over `embedding_method='nosana'` nodes; disabled with a `tier2_reason` under the hash fallback) candidate groups; `POST /api/graph/merge` merges explicitly listed node ids via `Neo4jClient.merge_nodes` (plain-Cypher transactional: repoint edges both directions preserving `r.source_doc`/`context`, union `source_docs`, absorb labels into `aliases`, longest summary wins, canonical = longest label → newest → smallest id). `AUTO_MERGE=exact` env opts into automatic tier-1 merging at ingest (off by default). `delete_source` removes membership + that doc's edges and deletes a node only when its membership empties. `get_graph_data_by_source` includes boundary nodes so every returned edge endpoint is present — the frontend's D3 forceLink hard-crashes otherwise; preserve that invariant in new per-source queries.

### Sandboxed audits and analytics (Daytona)

Beyond the per-ingest `verify_graph`, `DaytonaExecutor` in `src/agent/daytona_exec.py` has three more entry points. All of them return `ok: true|false` results with fixed error literals, like `verify_graph`, and never 500 on an infrastructure failure:

- `analyze_graph` (`GET /graph/analytics`): Cypher-side histograms and degree ranking are always present. Sandboxed structural metrics (PageRank, betweenness, capped by node/edge limits) sit under `structure`. When the sandbox run can't happen, `structure` becomes `{"ok": false, "error": ...}` instead of failing the whole response.
- `verify_graph_fanout` (`POST /graph/verify/fanout`): one ephemeral sandbox per source (largest sources first, `limit` caps the count), launched together behind a semaphore (`FANOUT_MAX_CONCURRENCY`, clamped 1..32). One source failing gives an item with `ok: false`, not a failed batch.
- `verify_graph_sweep` (`POST /graph/verify/sweep`): runs the same sub-graph, replicated, at each requested N. The sizes run **one after another on purpose**, because overlapping them would compete for the account's CPU budget and invalidate the measurement. The response is labeled `replicated` so it is never read as N distinct sources. `short_by` reports sandboxes Daytona refused at the account CPU ceiling (10 on the demo account) rather than averaging them away.

Progress reaches the executor through an injected `on_event` sink (the route wraps `ws_manager.broadcast`). The executor never imports a transport, and a sink that raises is logged and ignored.

### Query history

`src/agent/history.py` `QueryHistory` (`app.state.history`) is an in-memory, per-process ring of `/ask` results (50 entries; up to 20 can be pinned as `saved`, and only unsaved entries are evicted). Like `jobs.py`, it's generic and doesn't import `src.main`/`src.agent.core`; recording happens in the route. It's synchronous on purpose: no I/O and no start/shutdown hooks.

### WebSocket coupling

`GraphAgent._get_ws_manager` lazily imports `ws_manager` from `src.main` to avoid a circular import — the agent module must not import `src.main` at top level. Broadcast payloads: `{"type": "graph_update", "nodes": [...], "edges": [...]}` (append-only incremental merge) and `{"type": "graph_merge", "removed_ids": [...], "canonical": {...}, "edges": [...]}` (frontend removes merged nodes in place, falling back to a full redraw on any error — never leave the graph blank). Also on the same socket: `job_update` (job queue), `fanout_update` and `sweep_update` (audit progress, drawn live by the frontend panels). Source replacement sends `graph_reset`, prompting a full refetch to remove stale IDs. Unknown message types are ignored; socket disconnect also triggers polling/refetch.

## Notes

- Async throughout: Neo4j uses the async driver, all client calls are `await`ed. Blocking work (DNS, HTML parsing) goes through `asyncio.to_thread` / the loop's `getaddrinfo`. Keep new code async.
- `load_dotenv()` runs in `src/main.py` *before* the app-module imports — keep it there so import-time env reads see `.env`.
- The frontend escapes all dynamic content through its `esc()` helper before any `innerHTML` write — route new dynamic values through it too (scraped/LLM content is untrusted).
- Tests are offline by default (mocked LLM/Neo4j); Neo4j-dependent tests are marked `integration` and skip without `NEO4J_URI`/`NEO4J_USER`/`NEO4J_PASSWORD`.
- Versioned SHA-256 namespaces isolate new source graphs; legacy seeded IDs retain their md5 prefix; cross-document duplicates are handled by the suggest-only merge feature (see Entity dedup/merge above).
- New Source identities are separate from titles. URL IDs hash the full canonical URL, while durable display URIs omit query values. Atomic source/version publication, tombstones, explicit legacy migration and semantic re-embedding are documented in `docs/M1_UPGRADE.md`. Legacy title collisions cannot be reconstructed.


## Optional durable workflows (M3)

`STATE_DB_PATH` enables local SQLite adapters; unset keeps the legacy memory
queue/history. HTTP routes accept sync or async store methods. Commands are
strict versioned JSON; private text/file payloads never enter public job params
or event metadata, and are purged at terminal state. Claims reserve shared slots
and attempts transactionally; progress/results require the current lease token.
Cancellation awaits cleanup before releasing the slot. Neo4j IngestOperation
receipts commit with publication and prevent crash recovery from republishing
an old command after a later refresh/delete. Source versions remain in Neo4j.
Read docs/M3_CONTRACT.md, docs/M3_ADR.md and docs/M3_UPGRADE.md before changing
recovery, retention or deployment. Supported topology is one API process and
local disk; token/dollar budgets and shared API event/rate delivery remain open.


## Private workspaces (M4)

AUTH_MODE=private uses IdentityStore sessions/membership checks before workspace
resource lookup. Routes resolve request.state.resources; root resources remain
only for explicit local mode. WorkspaceNeo4jClient scopes static owned Cypher
labels/types/indexes and traversal intermediates. Each workspace owns SQLite
jobs/history and an injected broadcast manager; principal membership is rechecked
before sends and durable command stages/chunks/publication. See M4_CONTRACT and
M4_UPGRADE for cookie/CSRF, revocation, provider disclosure and offline purge.
